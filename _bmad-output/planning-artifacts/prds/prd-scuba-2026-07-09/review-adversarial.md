# Adversarial Review — Reef-State Model Redesign PRD

Cynical, edge-case pass on `prd.md` + `addendum.md`, checked against `reef-state.ts`, `effective-fishing.ts`, and the actual `src/data/*.json` feeds. Verdict: the thesis is sound but the two headline claims — "the 3 fish-driven thriving overrides migrate to computed" (SM-1) and "the fish pillar is a defensible B/B₀ read against a regional baseline" (FR-8) — are contradicted by the model's own preserved invariants and by the data that actually exists. Findings below in severity order.

## Critical

- [critical] The fishing gate the PRD preserves is the exact thing that blocked the editors — FR-10 cannot reproduce 2 of the 3 headline overrides (§FR-10 / FR-11 / SM-1) — `abrolhos-banks` and `chumbe-island-tanzania` carry GFW-measured effort of **301 h** and **352 h** respectively (verified in `fishing-pressure.json`), both of which land in the **moderate** band. `reconcile(moderate, no-take)` returns `moderate` (not `protected`, not `paper-park`), and `fishingAllowsImproving("moderate")` is **false**. FR-11 explicitly preserves that gate ("only protected/low/unknown permit Improving"). So both sites are structurally barred from computing `thriving` — which is *why an editor overrode them in the first place*. FR-10's "primary reproduction test" (each of the 3 must compute to thriving) will fail for 2 of 3, and SM-1's "the 3 fish-driven thriving overrides migrate to computed" is not achievable without breaking FR-11. Fix: state up front that overrides existing to defeat the fishing gate cannot be retired by a model that keeps the gate; either scope SM-1 to `torre-guaceto` only, or add an explicit "strong biomass evidence relaxes the fishing gate under protection" rule and accept the invariant change consciously.

- [critical] The FR-4 coral gate is vacuous when coral data is absent, so coral-less fish+fishing sites get the strongest label (§4.1 / FR-4 / SM-C2) — the preserved gate only blocks a *measured* coral decline (`bestCover !== null && bestCover < bestCoverBefore`). When there is no coral pillar, `coralFalling` is false and the Improving gate passes vacuously. `torre-guaceto-italy` has **zero** records in `reef-health.json` (no coral, no thermal), so it would reach Improving on Fish+Fishing alone. That directly violates SM-C2 ("Improving still requires holding/rising coral") — absent coral is not holding/rising coral, it is no coral. Any 2-pillar coral-absent reserve can now earn the atlas's strongest verdict at Provisional/Sparse confidence. Fix: make the Improving gate require coral to be *present and* holding/rising (positive assertion), not merely "not measured falling"; absent coral should cap the verdict at Stable.

- [critical] Data claim is false: the 3 thriving overrides have no transect fish-series coverage (§1 / FR-10 / addendum §A) — the PRD and addendum assert "all 4 overrides have direct fish-series coverage." Verified: `torre-guaceto`, `abrolhos-banks`, `chumbe-island` return **0** matches in `fish-biomass-series.json` (RLS), `reef-fish-abundance-series.json` (REEF), `agrra-reef-series.json`, and `fish-abundance-series.json`. Their only structured fish coverage is `blue-parks.json` (3 hits). `torre-guaceto` additionally has no coral, no thermal, and no coral-series record anywhere — its entire fish basis is prose in `manualReefStateBasis`. The FR-10 regression harness is being specced against fish inputs that the pillar can't actually read for the very sites it must reproduce. Fix: correct the claim to "blue-parks evidence only," and confirm the Fish-Community Pillar can compute from `blue-parks.json` structured fields (not prose) before making these the reproduction test.

- [critical] B/B₀ is unsupported by the data and contradicts the "relative, never absolute" rule (§FR-8 / Glossary / addendum §B) — the Glossary says "Normalization is relative to baseline, never a global absolute threshold" and FR-8 says "not an absolute number," yet addendum §B hard-codes global absolute anchors (B₀ ≈ 1,000–1,200 kg/ha, healthy ≥0.5 B₀, collapse <0.25 B₀). Worse, the file that FR-8 names as the fish reference, `reef-check-fish-regional.json`, holds **indicator densities** (individuals per 100 m², from a 1,107-reef *global* Reef Check survey 1997–2001) — not per-basin unfished biomass, and not kg/ha. The override bases mix units freely (torre: density ratio "3–7× denser"; abrolhos: "148 g/m²"; chumbe: "886 kg/ha"). There is no data path from a density benchmark to a kg/ha B/B₀. Fix: either ingest an actual unfished biomass reference per basin, or drop the B/B₀ framing and score the fish pillar as an MPA-contrast ratio (inside vs adjacent fished), which is what the evidence actually supports — and reconcile the addendum's absolute anchors with the Glossary's "never absolute" rule.

## High

- [high] "Regional Baseline" for coral is a degraded recent mean, so "at/above baseline = healthy" rewards already-collapsed reefs (§FR-5 / addendum §B / STATE_DEF) — `coral-cover-regional.json` Caribbean is a GCRMN regional *average* sitting at ~14–16% (down from 18% in 1983). Normalizing "at or above baseline" as good means a 16%-cover Caribbean reef reads healthy, and per addendum §A a reef "far below regional baseline" hard-triggers Declining — so the trigger point is ~15%, not a pristine reference. This is textbook shifting-baseline syndrome and it contradicts `STATE_DEF.thriving` ("close to its natural baseline"). The reference semantics are also inconsistent across pillars: coral against a degraded regional mean, fish nominally against an *unfished* B₀ — two different meanings of "baseline" being averaged into one composite. Fix: state explicitly that coral baseline is the *current regional mean* not a natural reference, rewrite `STATE_DEF` copy accordingly, and make coral/fish reference semantics consistent (both current-relative or both unfished-relative).

- [high] No fish-direction guardrail symmetric to FR-4, so SM-2 is unenforceable for the fish chart (§FR-4 / FR-13 / SM-2) — FR-4 stops a *falling coral* reef from reading Improving, but there is no equivalent rule for the fish-biomass chart. A reef with a visibly collapsing fish-biomass series but a strong coral/thermal/fishing read (fish pillar down-weighted by low confidence, or absent) can still compute Improving/Stable while the on-page fish chart trends down — a visible contradiction. SM-2 demands "zero locations where the label visibly contradicts its own coral-cover *or fish-biomass* chart," but the engine only gates on coral. Fix: add a fish-falling gate mirroring `coralFalling`, or scope SM-2's guarantee to coral only and admit the fish chart can disagree.

- [high] FR-10's success bar is defined after seeing the results, making SM-1 unfalsifiable (§FR-10 / SM-1 / §8) — "the migration target is not fixed up front — the regression diff runs first, then the acceptable divergence set is agreed," and every divergence may be "(a) accepted as a model improvement." A metric whose pass threshold is set post-hoc from the output it measures cannot fail; any wrong verdict can be relabeled "improvement." Fix: commit to at least one falsifiable pre-registered criterion (e.g. "the 3 thriving overrides compute to thriving OR are retained with a cited reason; zero silently accepted downgrades"), decided before the diff is run.

- [high] The apex/indicator "proxy" is a fish-pillar backdoor that lets sightings clear the FR-3 floor and manufacture a label (§FR-15 / FR-3) — FR-15 asserts sightings "never constitute a Pillar Score by themselves," yet the same requirement says they "provide a coarse apex/indicator-species proxy for the Fish-Community Pillar where no biomass survey exists." That is the sightings *being* the fish pillar's data. Once a sightings-derived fish proxy counts as a "true condition pillar," it satisfies the FR-3 floor, and combined with the vacuous coral gate (finding above) plus `fishingAllowsImproving("unknown") === true`, a reef with only sightings + no fishing data could climb to a positive label. This is exactly the "sightings sneaking a positive label past the floor" case the redesign claims to prevent. Fix: rule that a sighting-derived proxy can raise confidence but never by itself satisfy the FR-3 "condition pillar present" test, and never participate in the Improving gate.

- [high] The one override that *can* pass the fishing gate falls in an uncovered fish basin (§8 res.6 / FR-8) — `torre-guaceto-italy` is Mediterranean; `reef-check-fish-regional.json` covers only `indo-pacific` and `atlantic`. So the single thriving override whose fishing read (`low` + no-take → `protected`) permits Improving is exactly the one with no regional fish baseline → documented fallback + *lowered* confidence. Lower pillar confidence (`cᵢ`) shrinks its weight in the composite and pushes the verdict toward Provisional/Sparse — undercutting a confident migration. The migratable case is the least supported. Fix: add a Mediterranean fish reference (or an MPA-contrast fallback that doesn't need a basin baseline) before claiming torre-guaceto migrates cleanly.

## Medium

- [medium] Thermal is a nightly-overwritten current snapshot, so build-time verdicts will flicker with transient heat (§FR-7 / addendum §A) — `reef-health.json` thermal is `source: noaa-crw-live`, `fetchedAt` today, one row per site. Scoring on continuous current DHW means a passing heat spike flips a reef toward Declining on the next nightly build and back afterward, with no new survey. The old worst-ordinal read was coarse but stable. FR-1's consequence "re-running on unchanged inputs yields an identical verdict" is technically true but misleading: the thermal input *is not* unchanged between builds. Fix: define smoothing/hysteresis (e.g. require sustained DHW, or damp thermal's weight) and rewrite the determinism consequence to acknowledge nightly thermal churn.

- [medium] DHW→0..1 rescaling has no defined cap or reference (§FR-7 / addendum §A/B) — addendum says "CRW anomaly-vs-site-MMM already baked in," but DHW is an unbounded accumulator (0 to 20+), not a 0..1 score. Without a stated cap (e.g. 8 DHW = Alert 2 = score 0) the thermal pillar's normalized value is undefined, and its contribution to the equal-weighted composite is arbitrary. Fix: specify the DHW→score mapping and its saturation point in the addendum.

- [medium] Confidence is used two ways and the hard triggers ignore it, creating inconsistent treatment (§FR-1 / addendum §A) — the composite down-weights low-confidence pillars via `cᵢ`, but the hard guardrails (coral far-below-baseline → Declining, thermal rank ≥3 → Declining, `coralFalling` → not Improving) are binary and confidence-blind. So a single stale, low-confidence coral reading is near-weightless in the composite yet can still hard-trigger Declining — or a stale coral drop hard-blocks Improving while contributing almost nothing to the score. Fix: decide and document whether hard triggers respect a minimum pillar confidence, or state deliberately that guardrails are confidence-independent and why.

- [medium] Equal importance weights + confidence weighting still let one basin-coarse pillar swing a 2-pillar verdict 50% (§FR-1 / §8 res.6 / addendum §A) — with only two pillars present (common: the coral-absent override sites), each contributes up to half the composite. A fish pillar normalized against a 2-basin, 25-year-old global-mean benchmark carries the same importance weight as a fresh multi-source coral pillar. Confidence weighting dampens but does not remove this, since importance is equal by policy. Fix: consider a floor on how much a single fallback-baseline pillar can move the verdict, or require ≥2 *condition* pillars before a non-Stable label.

- [medium] An override silently supersedes even a Well-surveyed 4-pillar computed verdict (§FR-16) — `manualReefState ?? computed` means a cited override wins regardless of how strong the computed signal is; FR-16 requires a basis but nothing about reconciling with a high-confidence contradiction. An editor could pin `thriving` on a reef the model computes as Declining at Well-surveyed confidence, and the only trace is the "editorially adjusted" flag. Fix: require overrides that contradict a Well-surveyed computed verdict to carry an explicit acknowledgment of the disagreement, and surface both values in the breakdown.

- [medium] The `channel-islands-usa` retained-override rationale is exactly what the new thermal pillar is supposed to score (§FR-17) — it's kept at `pressure` because "recovery has not held under warming," but warming/heat stress is precisely the new Thermal Pillar's job. The justification only survives because *recurrence* history is deferred to v2 (FR-7). As written it reads as if the fish pillar's blind spot justifies retention, when the real reason is the deferred thermal-history ETL. Fix: restate the retention reason as "requires thermal recurrence history, deferred to v2," so the example doesn't imply the live thermal pillar is inadequate.

- [medium] Determinism consequence contradicts freshness-driven confidence (§FR-1) — FR-1 claims "no time-of-day dependence except documented freshness decay," but freshness feeds pillar confidence `cᵢ`, which weights the composite *and* sets the Confidence Tier. So both the tier and (via `cᵢ`) potentially the verdict drift as data ages with zero new input. Fix: acknowledge that verdict/tier are a function of wall-clock age, not just of the data values.

## Low

- [low] SM-1 as a bare count is gameable (§SM-1 / FR-17) — "count drops from 4" can be satisfied by deleting a non-reproducing override and accepting a wrong verdict; the real safeguard is the per-override diff, not the count. Also the "10 basis-annotated records" are not overrides today, so they cannot "reduce" anything — the metric conflates latent context with active overrides. Fix: make SM-1 "every removed override's computed verdict matches its retired value (or is a documented, accepted improvement)," not a headcount.

- [low] SM-3 / SM-C1 leave "positive label" undefined, so thin-evidence Stable escapes the counter-metric (§SM-3 / SM-C1) — the FR-3 floor blocks below-floor sites into Not surveyed, but a just-above-floor site lands in **Stable**, not Improving. SM-C1 only guards against "low-confidence *positive* labels" spiking. If Stable isn't counted as positive, coverage lift can be manufactured by producing thin-evidence Stable verdicts, cleanly passing SM-C1. Fix: define whether Stable counts as a "positive label" for SM-C1, and cap low-confidence Stable output explicitly.

- [low] "severe recent thermal alert" language is stale from the old worst-ever model (§addendum §A / FR-7) — with a single nightly snapshot there is no "recent" vs "historic" and no "worst-ever"; the wording implies a temporal comparison the data can't support. Fix: replace "recent/worst" thermal phrasing with "current," consistent with the confirmed single-snapshot finding.
